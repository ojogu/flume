## Error envelope

Every error response follows the same envelope:

```json
{
  "status": "error",
  "message": "Human-readable description",
  "error_code": "machine_readable_code",
  "resolution": "How to fix it (sometimes)",
  "data": null,
  "role": null
}
```

| Field | Always present? | Description |
|-------|-----------------|-------------|
| `status` | Yes | Always `"error"` |
| `message` | Yes | Human-readable description of what went wrong |
| `error_code` | Yes | Machine-readable code — use this to handle errors programmatically |
| `resolution` | Sometimes | Hint on how to fix the error |
| `data` | Varies | Extra detail — null for most errors, contains Pydantic validation details for 422 |
| `role` | Always | Reserved; always `null` |

## HTTP status codes

| Code | When |
|------|------|
| `400` | Validation failure (Gate 2–5) |
| `401` | Invalid or expired auth token |
| `403` | Missing or invalid API key |
| `404` | Resource not found |
| `409` | Conflict — resource already exists or is in use |
| `422` | Malformed request body (Pydantic schema validation) |
| `429` | Rate limit exceeded |
| `500` | Internal server error |
| `502` | External API error (e.g. downstream service failure) |

## Error codes

| `error_code` | HTTP | Description |
|--------------|------|-------------|
| `unauthorized_user` | 403 | Missing or invalid `X-API-Key` header |
| `bad_request` | 400 | General validation failure |
| `validation_error` | 422 | Malformed request body (Pydantic validation) |
| `not_found` | 404 | Resource not found |
| `resource_in_use` | 409 | Resource is already in use |
| `already_exists` | 409 | Resource already exists |
| `integrity_error` | 409 | Database integrity violation |
| `server_error` | 500 | Internal server error |
| `database_error` | 500 | Database error |
| `environment_variable_missing` | 500 | Server misconfiguration |
| `external_api_error` | 502 | Downstream service failure |
| `http_error` | varies | Generic HTTP error — check `message` for detail |

## Validation error catalog

All job submission errors are caught at intake time before any worker touches the
job. Each gate produces specific messages.

### Gate 1 — Schema (422)

Malformed request body. Pydantic rejects it before any custom validation.

```json
{
  "status": "error",
  "message": "Field required",
  "error_code": "validation_error",
  "data": [
    {
      "loc": ["body", "source", "type"],
      "msg": "Field required",
      "type": "missing"
    }
  ]
}
```

### Gate 2 — Registry lookup (400)

Unknown operation name.

```
Unknown operation 'compresss' at position 0. Valid operations: trim, cut, compress, ...
```

### Gate 3 — Param validation (400)

| Cause | Message pattern |
|-------|----------------|
| Missing required param | `Missing required param 'start' for 'trim' at position 0` |
| Wrong type | `Param 'width' for 'resize' at position 0 must be an integer` |
| Enum value not allowed | `Param 'quality' for 'compress' at position 0 got 'super'. Allowed values: low, medium, high` |
| Value below minimum | `Param 'start' for 'gif' at position 0 must be >= 0.0, got -1` |
| Value above maximum | `Param 'width' for 'resize' at position 0 must be <= 7680, got 99999` |
| Unknown param | `Unknown param 'color' for 'trim' at position 0` |
| Array too short | `Param 'clips' for 'join' at position 0 must have at least 2 items, got 1` |
| Array too long | `Param 'segments' for 'cut' at position 0 must have at most 50 items, got 100` |
| Invalid timecode format | `Param 'start' for 'trim' at position 0 has invalid timecode format 'bad format'` |
| Timecode below minimum | `Param 'start' for 'trim' at position 0 must be >= 0.0, got -5` |

### Gate 4 — Type compatibility (400)

| Cause | Message |
|-------|---------|
| Source type does not match step 0 | `Type mismatch at position 0: 'extract_audio' accepts [video] but previous step produces [audio]` |
| Step output does not match next step input | `Type mismatch at position 1: 'mute' accepts [video] but previous step produces [audio]` |

### Gate 5 — Pipeline spec (500)

Unexpected error during spec enrichment. This should not occur if Gates 1–4 passed.

```
Unexpected validation error
```

<Callout title="Gate 1.5 — join source.uri check (400)">
If the pipeline's first operation is `join`, Flume checks that `source.uri` is

```
source.uri is not used for join operation. Please provide 2-10 video URLs via the clips parameter instead.
```

## Common error scenarios

| Scenario | error_code | Fix |
|----------|------------|-----|
| No `X-API-Key` header | `unauthorized_user` (403) | Add the header |
| Invalid API key | `unauthorized_user` (403) | Check the key is correct and not expired |
| Malformed JSON body | `validation_error` (422) | Fix the JSON syntax |
| Unknown operation | `bad_request` (400) | Check operation names in [Operations](/docs/operations) |
| Wrong param type | `bad_request` (400) | Check param types in [Operations](/docs/operations) |
| Type mismatch in pipeline | `bad_request` (400) | Ensure adjacent steps are type-compatible |
| Upload not found | `not_found` (404) | Check the upload ID is correct |
