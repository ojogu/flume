# Authentication

Every API request is authenticated with an **API key** passed in the
`X-API-Key` header.

## API keys

Keys are generated in your dashboard. They are prefixed with `flm_` (so
secret-scanning tools can detect a leaked key) and look like:

```
flm_C40kpjzbjB8OPChdFWimkRbrsV6_ux_47v-wFCIHBy4
```

A key has a lifecycle:

- **active** — accepted for authentication.
- **revoked** — rejected. Revoked keys can no longer be used.
- Keys may have an **expiration date** (`expires_at`). Expired keys are
  rejected even if still active.

<Callout title="Store keys securely">
The full key is shown once, at creation time. Flume stores only a one-way
SHA-256 hash of the key, so it can verify a key but never recover the raw
value. If you lose a key, revoke it and create a new one.
</Callout>

## Sending the header

Every request that touches your data must include the header. The value is
the full key:

<Tabs items={['curl', 'Node.js', 'Python']}>
<Tab value="curl">
```bash
curl https://api.flume.ojogulabs.xyz/v1/utils/verify-key \
  -H "X-API-Key: flm_C40kpjzbjB8OPChdFWimkRbrsV6..."
```
</Tab>
<Tab value="Node.js">
```js
const res = await fetch('https://api.flume.ojogulabs.xyz/v1/utils/verify-key', {
  headers: { 'X-API-Key': 'flm_C40kpjzbjB8OPChdFWimkRbrsV6...' },
});
```
</Tab>
<Tab value="Python">
```python
import requests

res = requests.get(
    "https://api.flume.ojogulabs.xyz/v1/utils/verify-key",
    headers={"X-API-Key": "flm_C40kpjzbjB8OPChdFWimkRbrsV6..."},
)
```
</Tab>
</Tabs>

<Callout title="No SDK required">
Flume is a plain HTTP API. You can call it from any language with `curl`,
`fetch`, `requests`, or your HTTP library of choice. There are no official
SDKs — see [API Reference](/docs/api-reference) for the endpoints.
</Callout>

## Verifying a key

`GET /v1/utils/verify-key` checks that the key in the header is valid and
returns read-only metadata about it:

```json
{
  "status": "success",
  "message": "Success",
  "data": {
    "valid": true,
    "key_prefix": "flm_C40kpjzb",
    "name": "my key",
    "expires_at": null,
    "last_used_at": "2026-08-16T12:05:00Z",
    "status": "active"
  },
  "role": null
}
```

Field notes:

- `key_prefix` — the first 8 characters of the key's secret. This is what
  the dashboard shows so you can identify a key without exposing the full
  value.
- `last_used_at` — updated whenever a key successfully authenticates a
  request.
- `status` — `active` or `revoked`.

## Errors

A missing, invalid, expired, or revoked key produces a `403 Forbidden`
response:

```json
{
  "status": "error",
  "message": "Unauthorized",
  "error_code": "unauthorized_user",
  "data": null,
  "role": null
}
```

- `Missing X-API-Key header` — you did not send the header at all.
- Invalid or expired key — the key could not be matched to an active,
  non-expired key.
