## Purpose

Complete reference of events emitted by Flume. Subscribe to specific events or use wildcards to receive all matching events.

## Event Naming

Events follow the `resource.action` convention:

| Pattern | Matches | Example |
|---|---|---|
| `*` | All events | `job.created`, `step.failed`, `ping` |
| `job.*` | All job events | `job.created`, `job.completed` |
| `step.*` | All step events | `step.started`, `step.completed` |
| Exact match | Single event | `job.completed` |

## Job Events

Events related to job lifecycle.

| Event | Description | Data Fields |
|---|---|---|
| `job.created` | New job submitted | `job_id`, `status`, `source_uri`, `source_type` |
| `job.processing` | Job started processing | `job_id`, `status`, `source_uri`, `source_type` |
| `job.completed` | Job finished successfully | `job_id`, `status`, `source_uri`, `source_type`, `source_metadata`, `error` |
| `job.failed` | Job failed | `job_id`, `status`, `error` |
| `job.cancelled` | Job was cancelled | `job_id`, `status`, `error` |
| `job.retried` | Job was re-queued after a transient failure | `job_id`, `status`, `source_uri`, `source_type` |

## Step Events

Events related to individual pipeline steps within a job.

| Event | Description | Data Fields |
|---|---|---|
| `step.started` | Pipeline step started | `step_id`, `job_id`, `operation`, `step_index` |
| `step.completed` | Pipeline step finished | `step_id`, `job_id`, `operation`, `step_index`, `output_artifact` |
| `step.failed` | Pipeline step failed | `step_id`, `job_id`, `operation`, `step_index`, `error` |

## Test Event

Used to verify webhook connectivity.

| Event | Description | Data Fields |
|---|---|---|
| `ping` | Test/verification event | `message` |

Sent via `POST /webhooks/{id}/test`. Returns the HTTP status and response body immediately.

  }
