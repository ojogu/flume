## Headers

Every webhook request includes these headers:

| Header | Value | Description |
|---|---|---|
| `Content-Type` | `application/json` | Payload format |
| `X-Signature-256` | `sha256={hmac}` | HMAC-SHA256 signature |
| `X-Event-ID` | `{event_id}` | Unique event identifier |
| `User-Agent` | `Flume-Webhook/1.0` | Sender identification |

## Signature Verification

Verify the `X-Signature-256` header to ensure the payload came from Flume and wasn't tampered with.

### How It Works

1. Flume computes HMAC-SHA256 of the raw request body using your webhook secret
2. The signature is sent in `X-Signature-256: sha256={hex_signature}`
3. You compute the same HMAC and compare

### Verification Code

**Python**

```python
import hmac
import hashlib

def verify_signature(body: bytes, signature: str, secret: str) -> bool:
    expected = hmac.new(
        secret.encode(),
        body,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(f"sha256={expected}", signature)

# Usage
signature = request.headers.get("X-Signature-256", "")
body = request.body  # raw bytes

if not verify_signature(body, signature, WEBHOOK_SECRET):
    return Response(status=401)
```

**Node.js**

```javascript
const crypto = require('crypto');

function verifySignature(body, signature, secret) {
  const expected = crypto
    .createHmac('sha256', secret)
    .update(body)
    .digest('hex');
  return crypto.timingSafeEqual(
    Buffer.from(`sha256=${expected}`),
    Buffer.from(signature)
  );
}

// Usage
const signature = req.headers['x-signature-256'] || '';
const body = req.rawBody; // raw buffer

if (!verifySignature(body, signature, WEBHOOK_SECRET)) {
  return res.status(401).send();
}
```

> **Important:** Use the raw request body for verification. Do not parse and re-serialize JSON before verifying — this can change the byte sequence and invalidate the signature.

## Replay Protection

Use `X-Event-ID` to prevent replay attacks:

1. Store processed event IDs (with TTL, e.g., 24 hours)
2. Reject requests with duplicate event IDs
3. Event IDs are UUIDs — unique per event

```python
processed_ids = set()  # Use Redis/cache in production

event_id = request.headers.get("X-Event-ID")
if event_id in processed_ids:
    return Response(status=200)  # Already processed

# Process event...
processed_ids.add(event_id)
```

## Secret Management

| Rule | Description |
|---|---|
| Store securely | Treat webhook secret like a password |
| Never expose | Don't log or include in error messages |
| Rotate if compromised | Delete and recreate subscription |
| One-time display | Secret is shown once on creation — save it |
